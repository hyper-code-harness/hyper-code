# Browser sidebar: повторное использование Hyper UI и привязка вкладки

Исследование исходников `/Users/niquola/hyper-code2`; runtime не изменялся. Основной вариант: **открывать существующий web UI в iframe**, не писать второй чат. Ниже факты по коду; реальный iframe в Chrome, cookie policy расширения и reconnect CDP экспериментально не проверялись.

## 1. UI: готовый URL, embed и узкая ширина

- Канонический URL: `/agent/<id>?embed=1`. `src/agent/$route_$id_GET.ts` загружает агента, вызывает `ui.chatColumn({agentId})`, оборачивает результат в обязательный `#chat-panel[data-agent-id]`, добавляет inspector через `ui.agentMetaPanel`. `src/agent/$script_chat.js` управляет одним таким mount: отправка, вложения, история, прокрутка, tool cards. Это полноценный существующий чат, не отдельный compact API.
- `/a/<id>?embed=1` также работает: `src/a/$middleware.ts` передаёт запрос в `/agent/<id>` с сохранением query и заголовком `x-hyper-agent`. `/a/<id>/<page>` лишь передаёт контекст странице; комментарии про всегда пристыкованный чат устарели относительно текущего `src/ui/layout.ts`. Для sidebar предпочтительнее прямой `/agent/<id>`.
- Точное действие `embed=1` в `src/ui/layout.ts:21,237–264`: `overflow-hidden` у body; **не выводятся** quick-bar, mobile menu button, navMenu и постоянный dialog `#app-popup`. Сохраняются полный HTML shell, CSS, HTMX, chat.js, SSE client, meta.js, RPC/popup/control/screen scripts, secure-input-host и весь переданный main. Это режим вложенного окна приложения, а не sandbox или отдельная авторизация.
- **Embed сам по себе НЕ скрывает inspector.** В `src/ui/layout.ts:159–178` media query `max-width:700px` скрывает `[data-page="agent"] > aside[id^="agent-meta-"]` через `display:none!important`; chat занимает всю ширину. В iframe порог считается по viewport iframe. При ширине >700px inspector снова виден, `w-80` либо collapsed rail 2.5rem. Состояние collapse глобальное в `kv['ui:rightPanelCollapsed']`, не per-tab: `src/agent/$route_$id_GET.ts`, `src/ui/$script_meta.js`.
- Нюанс мобильного embed: header по-прежнему получает `padding-left:3.1rem` под кнопку меню, хотя embed её не выводит. Небольшое потерянное место, не причина переписывать чат.
- **Важный функциональный пробел embed:** удалён общий `#app-popup`, но `src/ui/$script_popup.js` и другие действия продолжают на него рассчитывать. Просмотр подробностей/файлов и secure-input нужно отдельно проверить: отсутствие host делает часть popup-действий неработоспособной. Если это критично для MVP, сначала открыть обычный `/agent/<id>` в узком iframe (inspector уже скрыт CSS); затем минимально разделить в core режим «без навигации, но с popup host», не дублировать чат.
- Escape в embed отправляет `{type:'ui.close-popup'}` в `window.parent` с `targetOrigin=location.origin`. Это рассчитано на same-origin родителя; в extension-origin sidebar доставка не произойдёт. Готового cross-origin bridge для bind/agent/tab в этом механизме нет. Обычные ссылки/redirect могут потерять `embed=1`; необходимо проверить fork, смену страницы и открытие файлов.

## 2. Создание агента, сообщения и realtime — переиспользовать runtime

- `src/agent/start.ts`: `agent.start({model,title?,workspaceDir?,systemPrompt?,tools?,visibility?})` выделяет id, сохраняет через `session.save`, обновляет live registry и уведомляет UI. Visibility `hidden` — только листинг, **не ACL**. Для sidebar серверный adapter должен атомарно выдавать/создавать одного агента на зарегистрированную вкладку; id не должен создавать браузер.
- `src/agent/createFromValues.ts`, `src/agent/$route_new_POST.ts`: существующий form-oriented flow создания; это не готовый JSON API bind-tab. У `agent.start` есть tools, у createFromValues такого opts нет.
- `POST /agent/:id`, исходник `src/agent/$route_$id_POST.ts`: text/plain либо формы с `text`, `files`/`file`; JSON `{text:...}` специально не разбирается, станет буквальным текстом. Пишет message и user event, attachments, syncAgentState, затем `agents.next_run_at` и `wakeWorker`. Ответ HTMX — 204, HTML — 303, API — `{ok,sendAt,messageIdx,attachments}`. Debounce обычно 5000ms, поддерживается `?debounceSeconds=`. Для iframe всё уже делает chat UI.
- `session.appendUserMessage` (`src/session/appendUserMessage.ts`) пишет message+event, **не планирует запуск само по себе**. Не копировать queue логику в extension и не мутировать `agent.messages/events`.
- `GET /agent/:id/events.html?offset=N` — HTML delta + self-replacing tail; `before`/`limit` — история. `compact=1` здесь только сохраняется в следующем tail URL, отдельного компактного renderer не включает. `GET /agent/:id/events?offset=N` — JSON `{id,model,events,nextOffset,isStreaming,usage}`. Источники: `src/agent/$route_$id_events.html_GET.ts`, `src/agent/$route_$id_events_GET.ts`; статус также `/agent/:id/status`, `/agent/:id/statusbar`.
- Realtime: `/procs/events?topics=agent:<id>,...`, `src/procs/events/$route__GET.ts`, `src/procs/events/client.js`, `src/ui/live.ts`. SSE — JSON invalidation, **не поток токенов**; hello требует refresh, keepalive 25s, HTMX refetch, tail watchdog 30s. Клиент закрывает stream в скрытом документе и переподключает при возврате. UI сам собирает topics с `[data-live-topic]`; второй SSE из extension для того же чата не нужен. Не держать iframe каждой фоновой вкладки активно подключённым.

## 3. Auth, cookies, CORS и frame policy

- `src/$middleware.ts`: optional password gate. При включённом пароле все обычные agent/SSE/assets требуют signed cookie; HTML GET без cookie → login redirect, остальные → 401. Записи с Origin другого host → 403; проверка включена только вместе с password gate. Исключения `/repl` и `/external/` не означают свободный API: у них свои механизмы; не применять их токены для sidebar.
- `src/auth/$route_login_POST.ts`, `src/procs/auth/cookie.ts`, `src/procs/auth/authenticate.ts`: логин form/JSON; cookie `HttpOnly; Path=/; SameSite=Lax`, срок 30 дней, `Secure` при HTTPS (учитывается `x-forwarded-proto`). Авторизация cookie, не Bearer в обычном agent API. Секреты/значения cookie при исследовании не читались.
- SameSite=Lax не гарантирует работу cross-site iframe. В обычном cross-site iframe cookie не отправляется как при top-level navigation. Поведение `chrome-extension://` зависит от Chrome, host_permissions и политики cookies: **не считать рабочим без реального теста**. Авторизация в отдельной обычной вкладке полезна, но сама по себе не исправляет third-party cookie ограничения. Не менять глобально cookie на SameSite=None ради MVP без оценки безопасности; предпочтителен trusted same-site deployment либо отдельный ограниченный pairing flow.
- В исследованном общем HTTP path (`src/procs/http/$start.ts`, `toResponse.ts`, `src/$middleware.ts`, `src/ui/layout.ts`) нет общей выдачи CORS headers, CSP frame-ancestors или X-Frame-Options. Это означает «код не запрещает», а не гарантию: reverse proxy и CSP manifest расширения могут запретить iframe/HTTP. Проверить итоговые response headers на фактическом URL и `frame-src` расширения; HTTPS-родитель может столкнуться с mixed content.
- Для навигации iframe CORS не нужен; fetch чата внутри iframe идёт на его собственный Hyper origin. CORS/pairing нужен отдельным API-вызовам extension service worker, не всем существующим чат-роутам. Нельзя добавлять `Access-Control-Allow-Origin:*` с owner cookies. Существующий Origin guard не признает extension-origin запись с cookie; нужен узкий authenticated route/контракт, а не глобальное отключение защиты.
- Auth — общий owner, не ограничения per-agent. `/agent/:id` и SSE topics не проверяют ownership вкладки. Не считать скрытую навигацию или переданный agentId границей безопасности.

## 4. CDP: существующая привязка НЕ является enforcement

Исходники: `plugins/browser/src/cdp/session.ts`, `send.ts`, `plugins/browser/src/browser/{tabs,navigate,evaluate,tabClose,closeSessions}.ts`.

- CDP endpoint: `CDP_BROWSER_URL` или `http://127.0.0.1:9222`. `browser.tabs({})` перечисляет все page targets, возвращает `{id,title,url}`; это CDP targetId, **не chrome.tabs tabId**. Нельзя связывать вкладки по URL/title (дубликаты). Extension должен получить точное соответствие tabId↔targetId доверенным способом (например, chrome.debugger target metadata, при подходящих permissions), подтвердить его серверу и проверять актуальность. Это рекомендация, не существующий код Hyper.
- `cdp.session({name?,targetId?})` хранит глобальный `ctx.state.cdp.sessions:Map`. Default name — `main`. При живом existing[name] функция возвращает его **не проверяя переданный targetId**. Если targetId не передан, создаётся новая background about:blank вкладка.
- `cdp.send({session?,method,params?,timeoutMs?})` вызывает session только с name. При любой ошибке закрывает handle, удаляет registry entry, создаёт session(name) **без исходного targetId**, повторяет команду. Поэтому после reconnect/timeout связанный агент может попасть в новую вкладку; side-effect команда может выполниться дважды. Простая предварительная `cdp.session({name,targetId})` не обеспечивает устойчивой связи.
- Browser actions обычно принимают свободный session, defaults сходятся к `main`; автоматической подстановки от agent.id нет. `browser.tabClose` принимает произвольный targetId; browser.tabs и browser-level CDP открывают доступ ко всем вкладкам. Ограничить только prompt и session-name недостаточно.
- `agent.start({tools:[...]})` + `src/agent/wireTools.ts`/`src/tools/schemas.ts` ограничивают **схемы на wire**. `src/tools/call.ts` ищет по полному registry, не проверяет opts.agent.tools! `tools:[]` означает все инструменты в schemas и сохраняется как null в `src/session/save.ts`. Поэтому это ещё не надёжный execution allowlist.
- Eval/bash дают произвольный доступ к HTTP/CDP и runtime; даже проверка только browser wrappers обходится raw fetch/WebSocket. При требовании строгой безопасности нельзя одновременно давать неограниченные eval/bash и обещать target isolation. `src/agent/run.ts` и `src/session/forAgent.ts` уже передают trusted session.agentId в tool call chain — подходящее основание для server-side policy, не параметр от модели.

## 5. Рекомендуемые границы интеграции

1. **Extension:** правая sidebar с iframe существующего `/agent/<id>?embed=1` (либо обычного URL до исправления popup). Хранит client/profile identity и tab lifecycle, переключает iframe, отображает статус «вкладка закрыта/связь потеряна». Не владеет transcript, queue, rendering и модельным циклом. Вкладку Hyper/собственный iframe не привязывать как рабочую.
2. **Private plugin `browserSidebar`:** guarded pairing + bind/get/revoke API; durable mapping `client/profile + tabId + generation → agentId + targetId + browser-instance`, unique constraint и идемпотентное создание. Навигация в пределах того же target сохраняет агента; закрытие/замена target инвалидирует связь. При рестарте/повторном использовании tabId нельзя молча отдавать старую привязку. Reconcile при reconnect. Не доверять agentId/targetId, присланным произвольной страницей.
3. **Core/browser минимальные изменения (отдельная будущая задача):** агент-scoped target policy на execution path, строгий execution allowlist, wrappers без произвольных session/target аргументов; retry только на исходном target и fail closed, без автоматического createTarget. Browser-level команды, произвольный Runtime.evaluate, eval/bash, delegation и вызовы других агентов требуют явной политики; безопаснее scoped actions без произвольного кода. Для действительно враждебной модели/страницы нужен ограниченный executor/transport, не только программная условность внутри full-privilege Bun.
4. **UI core:** не создавать новый чат. Если понадобится, отдельно исправить embed shell (сохранить popup, корректная Escape bridge, сохранение embed в переходах, отступ mobile header). Meta на ширине ≤700px уже скрыта; отдельная реализация не нужна.

`USER_PLUGINS` в этом runtime: `/Users/niquola/.hyper/user`. Private integration размещать прямым ребёнком, например `/Users/niquola/.hyper/user/browser-sidebar/`, с `package.json`, `SKILL.md`, `src/<namespace>/<function>.ts` и migration/routes по обычному grammar. Проверенные правила: `AGENTS.md`, `src/procs/modules/paths.ts`, `src/procs/modules/discover.ts`, `src/procs/boot/load.ts`; namespace collisions в user layer запрещены. Не класть существенную private integration в official `plugins/browser`, не маскировать core policy user override. `.hyper/` — только маленькие project-local procedures. Новые runtime функции создавать через dev.createFunction, существующие hot-reload + docs.validate; в этом исследовании ни одна функция не менялась.

## Приёмочные проверки перед реализацией

- Два одинаковых URL в двух tabs: разные агенты и точные targetIds; повторный open не создаёт дубль.
- Sidebar 360–500px: отправка, attachments, history, tool details, secure input, popup, focus/Enter, SSE reconnect и auth; ширина 701px показывает ожидаемое поведение inspector.
- Auth on/off, реальный extension-origin iframe и host_permissions, блокировка third-party cookies, корректный origin guard; никаких session/REPL secrets в URL, postMessage, логах.
- Закрытие target, Chrome restart, CDP timeout: действие не выполняется в новой/чужой вкладке и не повторяется опасно.
- Модель явно просит другой session/targetId, raw CDP, eval/bash, delegation: server-side deny, а не только скрытая schema или prompt. Пока эти проверки не реализованы, позиционировать sidebar как удобный UI доверенного full-access агента, **не tab-sandbox**.
